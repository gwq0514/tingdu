# 阿里云 2 核 2 GiB 试运行实测

测试日期：2026-10-28。以下是目标 Linux 实例上的结果，不是 Mac 模拟结果。

环境：x86_64、Alibaba Cloud Linux 3、总内存 1871 MiB；第一轮无 Swap，后续增加 2 GiB 磁盘交换空间测试；Docker 26.1.3、Compose 2.27.0。整个试验容器内存上限为 1500 MiB，CPU 上限 2 核。原模型、量化精度和总结请求参数均保持不变。

| 项目 | 已观察结果 |
|---|---|
| 独立部署 | Docker 镜像构建完成，服务仅绑定服务器回环地址 8768 |
| 模型校验 | SenseVoiceSmall INT8、GTCRN、pyannote segmentation、3D-Speaker 均通过原 SHA256 校验 |
| 9.21 秒合成中文音频导入 | 冷启动转写约 6.24 秒，正常输出中文 |
| 180 秒合成音频导入 | 约 40.88 秒完成，采样容器峰值 721.7 MiB |
| 约 10 分钟分段录音 | 147 段、602.112 秒音频；147 段转写完成，失败 0 段；每段提交后观察到的最大待转写数为 1 |
| 实时发言人标记 | 状态 done，单一合成声音标记为 1 位发言人 |
| 录音合并收尾 | 约 602.02 秒完成采集与转写收尾；当时最终发言人校正仍排队，不算已完成校正 |
| 总结期间录音优先 | 实际完整总结正在加载时开始合成录音；4.096 秒片段约 11.2 秒完成首段处理（含冷启动），无失败；录音结束后原总结自动恢复并返回 200，随后模型进程回收 |
| 音频阶段内存 | 持续分段时采样峰值 828.1 MiB；包含合并收尾的采样峰值 953.1 MiB |
| 最终发言人校正 | 10 分钟合成录音的最终校正持续计算超过 20 分钟仍未完成；本轮按超时记为未通过，主动停止测试推理，原声和文字保留；采样峰值 1085.9 MiB |
| 原 Q8 GGUF / 16K 总结（无 Swap） | 路径修正后请求约 8.21 秒失败，采样峰值 1350.8 MiB；独立诊断显示推理进程被系统终止，16K CPU KV buffer 为 1792 MiB |
| 原 Q8 GGUF / 16K 总结（2 GiB Swap，容器 swappiness=60） | 短测试转写的原始总结请求成功，约 152.85 秒；采样容器内存峰值 1500.0 MiB，交换占用峰值 1315.0 MiB；结束后推理进程组已回收 |

合成测试素材是重复的单一声音，用来验证运行容量和队列，不代表复杂会议中文识别准确率，也不能证明多人或重叠发言区分效果。各次内存峰值为定时采样的整个容器用量（包括文件缓存和测试客户端），不是精确单模型 RSS。转写耗时包含应用流程与状态轮询，不包含公网用户上传延迟。

当前仍是单人测试环境，保留测试工作文件，尚未完成多人隔离、本地历史持久保存和服务器临时文件自动清理。没有修改现有域名入口、网站反向代理或公网端口。不能宣称全功能已在 2 GiB 稳定对外上线。

本次总结输入来自约 9 秒音频，验证了原 16K 配置能够分配并输出短内容总结，未验证填满 16K 的长输入性能。当前可作为单人、顺序处理的验证环境，不能因此宣称完整长会议流程或多人并发稳定。
