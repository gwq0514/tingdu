# 云端 1.2.0-cloud.1：浏览器保存与临时处理隔离

仅在 `TINGDU_PROFILE=server-2gb` 且 `TINGDU_CLOUD_PRIVACY=1` 时启用。桌面静态页面、安装包、模型和16K上下文保持不变。

- 当前浏览器的 IndexedDB 保存录音、原文、总结、分类和订阅；重新打开网页可读取，音频通过本机 Blob 回听和下载。清除网站数据、无痕模式或换浏览器会影响这份历史，重要内容需导出或另存文件夹。
- 录音片段先写入本机 IndexedDB，再上传。完整处理结果的媒体与元数据写入成功后才向服务器确认清理，并校验版本，避免清理尚未保存的新结果。空间不足或保存失败时不确认清理，并显示提示。
- 每个浏览器使用独立的签名会话 Cookie（Secure、HttpOnly、SameSite=Strict），服务端对记录、媒体、导出、修改、删除、分类和订阅执行隔离。没有会话的 API 不返回资料，旧资料默认不可见。
- 处理副本在浏览器确认保存后删除；未确认的临时副本24小时到期后清理，模型仍忙时延后。旧资料必须通过受密码保护的迁移入口认领，旧服务器副本保留至用户确认清理，禁止自动清空。
- 清理后的本机原文仍可用于临时总结和提问；临时问答结束即清理服务端文本。重新做 ASR 需下载本机原声再上传，界面隐藏已清理记录的旧重试按钮。
- 云端上传100MB、录音10分钟、每会话2个在途任务、全局8个；创建次数限流与磁盘余量保护。模型大小、精度、上下文不缩水。
- 取消公共密码前必须验证实际浏览器保存、不同会话隔离和迁移；`/private/` 迁移与旧资料认领接口继续需要 owner 密码和代理专用密钥，公共代理必须清空客户端自带认领头。

验证包括两浏览器互不可见、跨会话直接访问/删除/导出拒绝、Cookie伪造与跨站写请求拒绝、完整保存后清理、保存失败不清理、刷新后回听、仅删音频/整条删除、本机问答、离线片段持久保存和桌面页面不变。
